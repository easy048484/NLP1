# EZNEXT 데모 시나리오 (2026-08-30)

발표·심사용 클릭 스크립트. 프로덕션(`https://nlp-1.vercel.app`) 또는 로컬에서 그대로 따라 하면 됩니다.

---

## 한 줄 피치

> 상속에는 세 가지 정책 공백이 있다 — ① 안심상속 통합조회 결과가 흩어져 해석이 어렵다,
> ② 상속포기·한정승인 3개월, 상속세 6개월 기한을 몰라 놓친다, ③ 자필유언 형식 요건·유류분
> 판단이 복잡하다. **EZNEXT는 대화형 AI가 이 셋을 순서대로 메운다.**

**신뢰 장치 3가지**(심사위원이 물어볼 것): 무재질문(공유 상태) · 숫자 검증(verify_numbers) · 판례 사건번호 자동 검증.

## 시나리오 A — 사후 (남겨진 가족)  ★메인

**페르소나**: 아버지가 2026년 6월 1일 돌아가신 30대 자녀. 상속 절차를 전혀 모른다.

| # | 행동 | 화면에서 나오는 것 | 강조 포인트 |
|---|---|---|---|
| 1 | 홈 → **"무료로 상담 시작"** | — | 회원가입 없이 바로 시작 |
| 2 | 온보딩 "상담 구분" → **"가족을 떠나보낸 뒤예요"** | — | axis=post_death, 이후 안내 순서가 사후용으로 바뀜 |
| 3 | 가족관계 → **"건너뛰고 상담 시작"** (시간 아끼려면) 또는 배우자+자녀 2명 입력 | — | 한 번 입력하면 이후 모든 에이전트가 재사용 |
| 4 | 입력: **"아버지가 2026년 6월 1일에 돌아가셨어요. 뭐부터 해야 하나요?"** | heir_navigator — "곧 다가오는 기한"(한정승인·상속포기 D-2), "남은 기한", "나의 할 일" 타임라인 + 체크리스트 + `.ics` 다운로드 | **정책 공백 ②** — 흩어진 절차·기한을 순서와 카운트다운으로 |
| 5 | **"안심상속 원스톱 조회결과부터 정리하기 →"** 클릭 → 위저드 | 기관별 카드(은행 예금 / 증권·펀드 / 부동산 / 자동차 / 퇴직연금 / 보험 / 대출·채무) | **정책 공백 ① — MVP 핵심** |
| 5a | 은행 예금 = "잔액까지 나왔어요" → **3,200만원**<br>부동산 = "잔액까지" → **3억 5천만원**<br>대출·채무 = "잔액까지" → **1억 2천만원**<br>나머지 = "없어요" → **"이대로 정리하기"** | asset_organizer — "확정된 자산·부채 목록", 순자산 **2억 6,200만원**<br>우측 패널: **"상속재산 요약"**(자산 3억 8,200만원 · 부채 1억 2,000만원), **"예상 상속세 ◐ 진행"** | 흩어진 조회 결과를 구조화 → 재산 규모가 즉시 잡힘 |
| 5b | (대안 시연) 📷 버튼 → 안심상속 조회결과 캡처 이미지 업로드 | AI가 이미지를 직접 판독해 같은 체크리스트에 반영 | "말로 설명 못 하겠으면 사진만 올리세요" |
| 6 | 입력: **"빚이 재산보다 많으면 어떻게 하나요?"** | heir_navigator — 빚<재산이라 "단순승인해도 상속인이 손해 보는 상황은 아니다" (빚>재산 케이스면 한정승인·상속포기 선택지 자동 표시) | 재산·부채를 이미 알고 있어 바로 판단 지원 |
| 7 | 입력: **"상속세는 얼마나 나와요?"** | tax_calculator — 재산가액을 다시 안 묻고, 거주자 여부·배우자 실제 상속액 등 몇 개만 확인 후 계산 | **무재질문** — asset_organizer가 모은 재산을 재사용 |
| 8 | 입력: **"자필로 쓴 유언장이 있는데 효력이 있나요?"** | decedent_estate — 선택지 → "직접 손으로 쓴 유언장" → 자서·날인·주소·연월일 요건별 신호등 + 관련 판례 사건번호 | **정책 공백 ③** + 판례 자동 검증 |
| 9 | 입력: **"유언장 효력도 다시 보고 상속세도 다시 계산해줘"** | 여러 에이전트가 한 턴에(decedent_estate → tax_calculator), 합성 답변 | 헤더 **"</> 개발자"** 켜서 실행 경로 `full`, 숫자 검증 결과 보여주기 |

**A 마무리 멘트**: "안심상속 결과 해석 → 기한 파악 → 상속세·유언장까지, 정보를 한 번만 입력하고 순서대로 안내받았습니다."

## 시나리오 B — 생전 (피상속인 본인)

**페르소나**: 은퇴를 앞둔 60대. 자녀에게 부담을 주고 싶지 않다.

| # | 행동 | 나오는 것 | 포인트 |
|---|---|---|---|
| 1 | 온보딩 → **"지금 준비 중이에요"** (pre_need) | — | axis=pre_need |
| 2 | 가족관계 입력: 배우자 + 자녀 2명 | 가족트리 | |
| 3 | 상담 화면 FunctionRail: **자산 정리 / 상속세 시산 / 법정상속분·유류분 / 유언 요건 점검** | 4개 기능 타일 | 생전 축 전용 구성 |
| 4 | **"자산 정리"** 타일 클릭 | asset_organizer — "예금·주식·펀드·부동산·보험·부채를 말씀해 주세요" | 📷로 은행 앱 잔액 캡처 업로드도 가능 |
| 4a | 입력: "예금 8천만원, 아파트 5억, 대출 없어요" → 나머지 카테고리 "없어요" | 자산·부채 목록, 순자산 | |
| 5 | **"상속세 시산"** 타일 | tax_calculator — 재산·배우자·자녀 수를 이미 알아 몇 개만 확인 후 예상 상속세 + 배우자 공제 효과 | **무재질문** |
| 6 | **"법정상속분·유류분"** 타일 → "한 자녀에게 다 주면 분쟁 위험이 있나요?" | heir_share_analyzer — 법정상속분 대비 유류분 부족 가능성(참고용), 전문가 확인 필요 사항 | 소송 승패 예측 안 함 (경계) |
| 7 | **"유언 요건 점검"** 타일 → "자필 유언장을 쓰려는데 형식이 궁금해요" | decedent_estate(prepare 모드) — 자필증서 요건 체크리스트 | |
| 8 | 우측 패널 확인 | 준비도 %, 가족관계·자산 정리·예상 상속세·유언 요건 4개 항목이 등록/진행으로 | **정보가 재질문 없이 이어짐** |

**B 마무리 멘트**: "자산 → 상속세 → 유류분 → 유언, 네 전문가가 같은 정보를 공유하며 이어서 안내합니다."

## 심사위원 예상 질문 대비

| 질문 | 답변 |
|---|---|
| "AI가 숫자를 지어내면?" | 여러 에이전트 답변을 합칠 때 `verify_numbers`가 금액·날짜를 원문과 정규식으로 대조, 하나라도 안 맞으면 합성본을 버리고 "⚠️ 확인필요" 배지. 프롬프트 약속이 아니라 코드 강제. |
| "판례는 진짜인가?" | decedent_estate가 인용하는 사건번호는 규칙 파일의 검증된 목록에서만 나옴(자동 검증). |
| "개인정보는?" | 유언장 원문·이미지는 저장 안 함(판독 후 폐기). 조회 결과의 계좌번호·예금주명은 서버 화이트리스트로 차단. |
| "은퇴 설계는 안 하나?" | 상속에 집중. 은퇴-상속 통합 설계는 확장 로드맵(엔진은 이미 구현돼 있음). |
| "실제로 배포됐나?" | `nlp-1.vercel.app`(프론트) + Railway(백엔드) 상시 가동. 지금 이 데모가 그 프로덕션. |

## 로컬 실행 (백업)

```bash
# 백엔드 (인메모리 세션, API 키는 .env)
cd apps/api
DATABASE_URL="" ./.venv/bin/uvicorn main:app --port 8000

# 프론트
cd apps/web
VITE_API_BASE_URL=http://localhost:8000 npm run dev -- --port 5173
```
브라우저 `http://localhost:5173`. (프론트 포트가 5173이 아니면 백엔드에 `CORS_ORIGINS` 환경변수로 그 포트를 추가.)
