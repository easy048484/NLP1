# heir_navigator 실험 시나리오 (2026-09-06)

웹 UI에서 직접 따라 하며 **(1) LLM-first 라우팅이 spec 설명만 보고 heir_navigator 를 고르는지**,
**(2) heir_navigator 의 절차 엔진(기한 계산·단계 추적·가드레일)이 의도대로 도는지**를 확인하는 스크립트입니다.
아래 "기대 결과"는 2026-09-06 에 로컬(LLM on)에서 실제로 돌려 얻은 값입니다. 남은 일수는 실험하는 날짜에 따라 달라집니다.

---

## heir_navigator 가 하는 일 (30초 요약)

사망 이후 상속인이 밟아야 할 절차를 **순서와 기한**으로 안내하는 에이전트입니다.

- 구조는 "결정론적 절차 엔진 + LLM 껍데기". 기한·서류·기관은 전부 `agents/heir_navigator/procedure/` 의 Python 데이터에서 나오고,
  LLM 은 입구(발화에서 사망일 등 슬롯 추출)와 출구(결과를 쉬운 말로 풀기)에만 쓰입니다.
- 절차는 9단계 DAG: 사망신고 → 안심상속 신청 → 재산조회 결과 확인 → 유언장 존재 확인 → 단순승인/한정승인/상속포기 결정 → 분할협의 → 상속등기 → 취득세 → 상속세.
- 기한 기산점이 단계마다 다릅니다: 사망신고 = 사망일+1개월, 승인·포기 결정 = "상속개시를 안 날"+3개월, 세금·안심상속 = 사망일이 속한 달 말일+6개월.
- 슬롯(사망일, 안 날, 빚 유무, 유언장 유무, 완료 단계)은 세션에 누적됩니다.
- 가드레일: "한정승인이랑 포기 중 뭐가 나아요" 같은 **선택 추천 요구는 LLM 을 태우지 않고** 선택지·결과만 설명하는 고정 응답으로 빠집니다.

| API | `http://127.0.0.1:8000` — `/health` 가 `{"llm":"on"}` 이어야 LLM-first 라우팅. `unconfigured` 면 키워드 폴백으로 돌고 있는 것 |

| 온보딩 | "상담 구분" → **사후**(가족을 떠나보낸 뒤) 선택 → 가족관계는 건너뛰어도 됨 |
| 라우팅 확인 | 헤더 **"</> 개발자"** 토글을 켜면 턴마다 실행된 에이전트·경로(`standard`/`full`)가 보임 |

## 시나리오 1 — 사망 직후 "뭐부터?" → 사망일 → 기한 계산 → 단계 완료 추적

**확인 목적**: 사망일을 되묻는 슬롯 수집, 기한 역산의 정확성, 완료 단계 반영.

| # | 입력 | 기대 결과 | 확인 포인트 |
|---|---|---|---|
| 1 | **아버지가 지난주에 돌아가셨어요. 뭐부터 해야 하나요?** | heir_navigator. 기한을 계산하려면 사망일이 필요하다며 **돌아가신 날짜를 되물음** | "지난주"는 날짜로 확정하지 않고 되묻는 것이 정상 (기한이 걸린 값이라 추정하지 않음) |
| 2 | **8월 30일에 돌아가셨어요.** | 사망신고 **2026-09-30**, 승인·포기 결정 **2026-11-30**, 안심상속·상속세·취득세 **2027-02-28**. "먼저 할 일 → 같은 날 함께 → 그다음 → 나중 기한 → 아직 못 하는 것" 순서 | 8/30+1개월, 8/30+3개월, 8/31(말일)+6개월 = 2/28 이 맞는지 손으로 검산 |
| 3 | **사망신고는 어제 했어요. 다음엔 뭘 해야 하죠?** | 사망신고가 완료 처리되고 **안심상속 원스톱 신청**이 "지금 할 일"로 올라옴. 승인·포기 기한(11/30)이 가장 빠르다고 강조 | 개발자 패널 `data.heir_navigator.completed` 에 `death_report` |

## 시나리오 2 — "빚 + 상속포기" 경계 → 안 날 기산점 → 선택 추천 가드레일

**확인 목적**: 빚 언급이 있어도 asset_organizer 가 아니라 heir_navigator 로 가는지(LLM 라우팅 경계), 기한이 지난 단계 경고, 가드레일.

| # | 입력 | 기대 결과 | 확인 포인트 |
|---|---|---|---|
| 1 | **빚이 많을 것 같은데 상속포기를 해야 하나요? 기한은 언제까지예요?** | **heir_navigator 단독** (asset_organizer 가 함께 뜨면 라우팅 오탐). 현재 구현은 "~해야 하나요"를 선택 추천 요구로 보고 **가드레일 고정 응답**(단순승인/한정승인/상속포기 3가지 결과 설명, 기한은 "안 날부터 3개월"로만 언급) | ⚠ 관찰 포인트: 가드레일이 먼저 걸려 사망일 되묻기가 생략됨. 이게 의도인지 팀 판단 필요 |
| 2 | **어머니가 2026년 7월 15일에 돌아가셨고, 빚이 있다는 건 8월 20일에 알았어요.** | "사망신고 기한(8/15)이 지났다"는 경고가 맨 위. 승인·포기 결정 **2026-10-15**(사망일 기준, "안 날은 따로 확인 못 해 사망일로 갈음"이라고 명시). 세금 **2027-01-31**. `has_debt=yes` | ⚠ "빚을 안 날(8/20)"은 `known_date` 로 잡히지 않음. 법적으로 빚 인지일은 특별한정승인 쪽 개념이라 틀린 건 아니지만, 사용자에겐 무시된 것처럼 보일 수 있음 |
| 3 | **한정승인이랑 상속포기 중에 뭐가 더 나아요?** | **추천 없이** 세 선택지와 결과만 설명, 법률구조공단(132)·변호사 상담 안내 | 가드레일이 LLM 을 우회한 고정 문구라 턴 1 과 같은 문장이 나오는 것이 정상 |

## 시나리오 3 — "유언장 없이 돌아가셨는데 절차는?" → 사망일 → 유언장 발견 시 decedent_estate 전환

**확인 목적**: 유언장 언급이 있어도 절차 질문이면 heir_navigator 로 가는지, 반대로 효력 질문이면 decedent_estate 로 넘어가는지(spec 설명만으로 경계 판단).

| # | 입력 | 기대 결과 | 확인 포인트 |
|---|---|---|---|
| 1 | **유언장 없이 아버지가 돌아가셨는데 상속 절차가 어떻게 되나요?** | **heir_navigator** (decedent_estate 가 아님). `will_exists=no` 로 기록하고 사망일을 되물음 | 개발자 패널에서 에이전트 확인 |
| 2 | **돌아가신 날은 2026년 8월 10일이에요.** | 사망신고 **2026-09-10** 이 임박(9/6 기준 4일)하다고 맨 위에 강조. 승인·포기 **2026-11-10**, 세금 **2027-02-28** | 임박한 기한이 순서상 앞으로 올라오는지 |
| 3 | **정리하다 보니 아버지가 자필로 쓰신 유언장이 나왔어요. 효력이 있는지 봐주세요.** | **decedent_estate** 로 전환. 유언장 사진 또는 내용을 요청 (`next_action=await_user_confirmation`) | 키워드 핸드오프가 아니라 LLM 이 spec 설명을 보고 고른 것. 이후 턴은 decedent_estate 가 답변 대기 중이라 계속 그쪽으로 고정됨 |

## 무엇이 이상하면 버그인가

- 시나리오 2-1 에서 **asset_organizer 가 함께 실행**되면 라우팅 오탐 (spec 경계 문구 재검토).
- 시나리오 3-1 에서 **decedent_estate 가 먼저 잡으면** heir_navigator/decedent_estate 의 description·예시 경계가 약한 것.
- 날짜가 위 표와 다르면 `procedure/deadlines.py` 문제 (LLM 은 날짜를 만들지 않으므로 서술 문제가 아님).
- 같은 세션에서 사망일을 다시 물으면 슬롯 누적(`state.py`) 문제.

## 커맨드라인으로 같은 시나리오 돌리기

웹 없이 재현하려면 `/chat` 에 같은 `session_id` 로 순서대로 POST 하면 됩니다.

```bash
curl -X POST http://127.0.0.1:8000/chat -H "Content-Type: application/json" \
  -d '{"session_id":"s1","user_message":"아버지가 지난주에 돌아가셨어요. 뭐부터 해야 하나요?","axis":"post_death"}'
```

응답의 `agents`/`path` 로 라우팅을, `data.heir_navigator` 로 누적 슬롯을 확인합니다.
