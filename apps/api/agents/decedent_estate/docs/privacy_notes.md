## 이 에이전트가 다루는 민감정보
- 유언장 본문에 포함될 수 있는 것: 성명, 주소, 주민등록번호, 계좌번호, 전화번호, 부동산 소재지, 재산 내역, 가족관계
- 요건 판정에 실제로 필요한 것: 성명, 주소, 날짜
- 판정에 불필요한 것: 주민등록번호, 계좌번호, 전화번호, 재산 내역
  → LLM 호출 단계에서 제거 대상 (최소수집 원칙)

## 보관에 대한 원칙
- 요청 처리 중 메모리: 필요 (판정에 불가결)
- 세션 상태: 필요 (확인 질문 답변을 받으려면 원본 맥락이 있어야 함)
- 영구 보관: 불필요, 피해야 함
- 이 에이전트 자체는 아무것도 저장하지 않음 (stateless 함수)

## 세션 연속성 처리 방식 (오케스트레이터 담당자와 협의 필요)
A안 클라이언트 보유 — 프론트가 유언장 텍스트를 들고 매 요청에 재전송.
     서버 무저장 완전 달성 / 새로고침 시 소실
B안 서버 세션 + 짧은 TTL — session_id 기준 30분~1시간 후 자동 삭제.
     자연스러운 흐름 / 짧게라도 서버에 존재
C안 추출값만 보관 (팀 제안) — 유언장 전문은 판정 직후 폐기,
     요건별 등급·질문 상태만 세션 유지.
     대화 연속성 유지하면서 민감정보 대부분이 서버에 남지 않음

## 팀 확인이 필요한 미해결 항목
- [ ] 대화 이력을 DB에 저장하는가? 저장한다면 보존 기간은?
- [ ] 업로드 파일(유언장 사진) 보관 정책은? (즉시 파기 여부)
- [ ] 서버 로그에 요청 본문이 기록되는가?
- [ ] 세션 처리 방식 A/B/C 중 어느 것으로 갈 것인가?
