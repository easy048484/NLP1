## 이 에이전트가 다루는 민감정보
- 유언장 본문에 포함될 수 있는 것: 성명, 주소, 주민등록번호, 계좌번호, 전화번호, 부동산 소재지, 재산 내역, 가족관계
- 요건 판정에 실제로 필요한 것: 성명, 주소, 날짜
- 판정에 불필요한 것: 주민등록번호, 계좌번호, 전화번호, 재산 내역
  → LLM 호출 단계에서 제거 대상 (최소수집 원칙)

## 보관에 대한 원칙
- 요청 처리 중 메모리: 필요 (판정에 불가결)
- 세션 상태: 필요 (확인 질문 답변을 받으려면 원본 맥락이 있어야 함)
- 영구 보관: 불필요, 피해야 함
- 이 에이전트 자체는 아무것도 저장하지 않음 (stateless 함수)

## 세션 연속성 처리 방식 — ✅ C안 확정 (2026-08-21, 팀장 결정)

A안 클라이언트 보유 — 프론트가 유언장 텍스트를 들고 매 요청에 재전송.
     서버 무저장 완전 달성 / 새로고침 시 소실
B안 서버 세션 + 짧은 TTL — session_id 기준 30분~1시간 후 자동 삭제.
     자연스러운 흐름 / 짧게라도 서버에 존재
**C안 추출값만 보관 — 채택.** 유언장 전문은 판정 직후 폐기,
     요건별 등급·질문 상태만 세션 유지.
     대화 연속성 유지하면서 민감정보 대부분이 서버에 남지 않음

### C안 구현 방식
오케스트레이터의 네임스페이스 규약(`orchestrator/handoff.py`)에 올라타서
구현했다. `AgentOutput.data["decedent_estate"]` 에 담은 것만 세션에 저장되고
다음 턴 `AgentInput.context["decedent_estate"]` 로 돌아온다.

담는 것 (`agents/decedent_estate/state.py` 의 `DecedentState`):
- `will_type`, `intent`, `has_draft`
- 확인 답변 — 자서/날인/주소봉투, 증인 참여/증인 결격
- 요건별 판정 결과 — 등급·condition_id·red_label·precedent_ids·추출값
- `pending_questions`

**담지 않는 것: 유언장 원문(user_message), 마스킹 이전 텍스트.**
`DecedentState` 에는 원문을 담을 필드 자체가 없다 — 실수로도 흘러 들어가지
않게 하기 위해서다. 회귀 방지 테스트는 `tests/test_decedent_state.py` 의
`test_*_excludes_will_text` 계열.

추출값(성명·주소 조각 등)은 판정 근거라 포함된다. 즉 "민감정보 0"이 아니라
"전문은 남기지 않고 판정에 필요한 최소값만 남긴다"는 절충이다.

세션 TTL은 오케스트레이터가 관리하며 현재 2시간
(`orchestrator/session_store.py` 의 `_SESSION_TTL_SECONDS`).
