### ⚠️ 평면 폴백 우선순위 — 지시와 반대로 구현 (리뷰에서 짚일 지점)

지시는 "네임스페이스 우선"이었으나 **평면 키 우선**으로 구현했다.

네임스페이스는 *지난 턴 저장 상태*, 평면 키는 *이번 턴 사용자 입력*이다.
지난 턴 값이 이기면 사용자가 답을 정정해 다시 보냈을 때 반영되지 않는다.

실제 병합은 **2단**으로 일어난다:

```
1단 handoff.build_agent_context : {**stored_context, **namespaced_override}
2단 state.load_state            : {**state, **flat_overrides}
```

두 계층 모두 *"저장된 값을 베이스로, 이번 턴 입력이 덮어쓴다"* 는 같은 방향이다.
`handoff` 의 명시적 원칙("사용자가 이번 턴에 명시적으로 답한 값이 우선")과 일치.

검증 테스트: `test_decedent_state.py::test_flat_key_this_turn_wins_over_stored_namespace`
(관련 3개 더: `test_load_state_falls_back_to_flat_keys`,
`test_broken_flat_value_keeps_namespace_state`, `test_load_state_from_namespace`)

→ PR #15 본문에 이 근거를 명시했고, 그대로 승인·머지됐다(평면 키 우선 확정).

조용히 흡수되고 있었다. 모델의 판단 자체(값 추출 내용)는 정확했다 — 순전히
파싱 계층 문제. 코드펜스 제거 전처리로 수정.

수정 후 재검증 결과:

| 필드 | 결과 |
|---|---|
| 주소 (`known_limitations.md` 2-1 예시) | ✅ `extraction_method="llm"`, `"서울 강남구"` 정확 추출 → 2-1 서술이 맞았음을 확인 |
| 녹음 5필드 중 3개(성명/처분의사/증인정확함확인) | ✅ LLM으로 정확 추출 (`"이순자"` 등) |
| 날짜·성명(각각 애매/부재 케이스로 구성한 텍스트) | `null` — 파싱은 정상, 모델이 정직하게 "못 찾음" 응답(재현 텍스트 자체가 근거 부족했음) |

**마스킹은 이 검증에서 처음부터 정확히 동작했다** — 주민등록번호·전화번호는
`[주민등록번호]`/`[전화번호]`로 치환, 성명·주소는 설계대로 원문 유지, 원문이
함께 실리는 경로 없음.

**남은 것**: 이 검증 과정에서 21개 테스트(`test_decedent_requirement_checker.py`
등)가 실제 정규식 `absent` 텍스트를 쓰면서 목(mock) 없이 진짜 API를 호출하고
있다는 것도 함께 드러났다 — 별도 이슈로 다룰 예정(테스트 격리, 현재 PR 범위
밖).

## 8. 로컬 환경 메모

CI(Python 3.12)와 로컬(Python 3.13) 차이로 걸린 것들:

- **`pip install -r requirements.txt` 가 로컬에서 실패한다.**
  `psycopg2-binary==2.9.9` 가 Python 3.13 휠을 제공하지 않아 소스 빌드하다 막힘.
  CI는 3.12라 정상. 필요한 패키지만 개별 설치하면 된다.
- 개별 설치한 것: `ruff`, `black`, `langgraph`, `sqlalchemy`, `alembic`,
  그리고 `psycopg2-binary` — **단 2.9.9 가 아니라 2.9.12 다.** 3.13 휠이 있는
  최초 버전이라 이걸로 올렸고, `requirements.txt` 의 핀은 건드리지 않았다.
  즉 로컬은 requirements.txt 와 다른 버전으로 돌고 있다(2026-08-23 기준).
  나머지 패키지도 개별 설치라 핀에서 벗어나 있다(예: fastapi 0.141.1 vs 핀
  0.115.0, pytest 9.1.1 vs 핀 8.3.3) — 로컬 통과가 CI 통과를 보장하지 않는다.
- **Python 버전 기준이 세 갈래로 갈려 있다** — 인수인계 메모는 3.11, CI
  설정(`.github/workflows/ci.yml:51`)은 3.12, 실제 로컬 venv는 3.13.9.
  3.11 은 이 개발 PC에 설치돼 있지 않다. 어느 것을 기준으로 삼을지는 팀 확인
  대기 중이며, 그때까지 위 이탈 상태로 작업한다.
- DB 테스트는 `DATABASE_URL` 이 없으면 자동 skip된다 (정상). 실측 15개
  (`conftest.py` 의 `with_db` fixture 사용분).
- **단 CI 는 skip 하지 않는다.** `ci.yml` 이 postgres 서비스 컨테이너를 띄우고
  `DATABASE_URL` 을 주입한 뒤 `alembic upgrade/downgrade/upgrade` 왕복까지
  돌린다. 그래서 CI 는 **401 passed, skip 0** 이고 로컬은 386 passed / 15
  skipped 다 — 차이 15개가 곧 DB 테스트다. 로컬에서 통과했다고 DB 경로가
  검증된 것이 아니다.
  (`db/base.py:8` 의 "DATABASE_URL이 없는 환경(지금 CI가 그렇습니다)" 주석은
  family_graph PR에서 CI 에 DB 가 추가되면서 사실과 달라졌다 — 별건으로 정리 필요)

#### ⚠️ `.env.example` 을 그대로 복사하면 테스트 3건이 실패한다

`copy .env.example .env` 를 하면 `DATABASE_URL=postgresql://postgres:devpass@
localhost:5432/family_assets` 가 설정된다. 로컬에 Postgres 가 떠 있지 않으면
`with_db` 를 쓰지 않는 `test_health.py` 의 3건(`test_chat_default_route`,
`test_chat_routes_to_decedent_estate`, `test_chat_routes_to_tax_calculator`)이
skip 되지 않고 접속을 시도하다 `sqlalchemy.exc.OperationalError` 로 실패한다.
접속 타임아웃 때문에 스위트 실행 시간도 늘어난다.

실측(2026-08-23):

| `.env` 상태 | 결과 | 소요 |
|---|---|---|
| `DATABASE_URL` 설정됨, Postgres 미기동 | 3 failed, 383 passed, 15 skipped | 78초 |
| `DATABASE_URL` 주석 처리 | **386 passed, 15 skipped** | 1.7초 |

Postgres 를 띄우지 않고 작업할 때는 `.env` 의 `DATABASE_URL` 을 주석 처리하는
쪽이 낫다. 실패 3건을 "원래 깨져 있는 것"으로 오해하기 쉬운 함정이다.

CI 에서는 같은 변수가 반대로 동작한다 — 거기엔 실제 postgres 가 함께 떠 있어
`DATABASE_URL` 이 있어야 정상이다. 즉 "설정하면 안 된다"가 아니라 **"DB 없이
설정만 하면 안 된다"** 가 정확한 규칙이다.
