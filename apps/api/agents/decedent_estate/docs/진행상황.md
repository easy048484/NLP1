### ⚠️ 평면 폴백 우선순위 — 지시와 반대로 구현 (리뷰에서 짚일 지점)

지시는 "네임스페이스 우선"이었으나 **평면 키 우선**으로 구현했다.

네임스페이스는 *지난 턴 저장 상태*, 평면 키는 *이번 턴 사용자 입력*이다.
지난 턴 값이 이기면 사용자가 답을 정정해 다시 보냈을 때 반영되지 않는다.

실제 병합은 **2단**으로 일어난다:

```
1단 handoff.build_agent_context : {**stored_context, **namespaced_override}
2단 state.load_state            : {**state, **flat_overrides}
```

두 계층 모두 *"저장된 값을 베이스로, 이번 턴 입력이 덮어쓴다"* 는 같은 방향이다.
`handoff` 의 명시적 원칙("사용자가 이번 턴에 명시적으로 답한 값이 우선")과 일치.

검증 테스트: `test_decedent_state.py::test_flat_key_this_turn_wins_over_stored_namespace`
(관련 3개 더: `test_load_state_falls_back_to_flat_keys`,
`test_broken_flat_value_keeps_namespace_state`, `test_load_state_from_namespace`)

**→ PR #15 본문에 이 근거를 명시할 것.** 리뷰어는 지시대로 네임스페이스 우선을
기대하고 볼 가능성이 높다.

### 동작 확인

오케스트레이터 2턴 대화로 검증:
```
1턴: 유언장 + 자서 답변                  → 날인 PENDING
2턴: 날인 답변만 (will_type·자서 재전송 X) → 자서 GREEN, 날인 GREEN
세션 저장 내용에 원문 포함 여부: False
```

### 코드 재확인 결과 (2026-08-21, Claude Code)

- `LEGACY_FLAT_CONTEXT_AGENTS` 빈 집합 확인. `AgentName` 세 값 전부 미포함 실측.
- `test_orchestrator.py` 테스트는 **무의미해지지 않았다** — 네임스페이스 키 생성,
  평면 키 통과, **세션 왕복**(1턴 `data` → 2턴 `context`) 3가지를 검증한다.
  누군가 LEGACY 집합에 되돌리면 `KeyError` 로 실패한다.

### 후속 커밋 예정 (#15 브랜치, 새 커밋으로)

1. **`test_legacy_flat_context_set_is_empty` 삭제** — 동작이 아니라 상수 값을 단언.
   위 테스트가 이미 같은 회귀를 잡으므로 중복이고, 네 번째 에이전트를 LEGACY에
   임시 등록하는 정당한 상황에서 실패한다(상수 유지 결정과 모순).
2. **`_flat_overrides` 빈 문자열 필터** — 현재 `is not None` 으로만 걸러서
   `will_type=""` 이 네임스페이스 정상 값을 덮어쓴다. 화이트리스트가 뒤에서 걸러
   재질문으로 이어지므로 치명적이진 않으나, 유족 대상 UX에서 "아까 답했는데 또 묻는"
   상황이 된다. `v is not None and v != ""` 로 수정.
   (`has_draft=False` 는 bool이라 영향 없음 — 의도된 동작)

### 상수 제거 여부 — 유지로 결정

`LEGACY_FLAT_CONTEXT_AGENTS` 는 빈 집합이라 분기 2곳(`handoff.py:81, 102`)이
현재 죽은 코드다. 그래도 유지한다 — 죽은 분기 2줄 비용이 낮고, 네 번째 에이전트를
규약 적용 전 임시로 붙일 자리로 쓸 수 있다. 제거하려면 공용 파일이라 지원님 승인 필요.

`apps/api/llm/client.py` 가 새로 생겨 `LLM_PROVIDER` 로 claude/upstage/k-exaone 을
고를 수 있는데, decedent_estate 는 아직 자체 `llm_client.py`(Anthropic SDK 직접)를 쓴다.
파일 주석에 "4단계에서 연결하세요"라고 적혀 있다.

전환하면 Upstage/K-EXAONE 도 쓸 수 있지만, JSON 응답 파싱·타임아웃·마스킹 전제를
다시 맞춰야 해서 범위가 크다. **6-2(이름 수정)만 먼저 하는 게 안전하다.**

### 6-6. 판정 결과 병합 경로 (별도 이슈 필요)

**#15 범위 밖으로 남겨둔 것.** 원문 없이 저장된 판정 결과에 새 확인 답변만
병합하는 경로가 아직 없다. 지금은 매 턴 원문이 다시 오는 것을 전제로 평면 폴백이
받쳐주고 있다.

프론트가 원문 재전송을 멈추면 필요해진다 — 원문이 없으면 날짜·주소·성명을 다시
추출할 수 없어서, `check_requirements()` 재실행이 아니라 저장된 결과에 답변만
얹어야 한다. `CLAUDE.md` 빌드 순서 6)에 ⚠️ 로 명시해둠.

## 8. 로컬 환경 메모

CI(Python 3.12)와 로컬(Python 3.13) 차이로 걸린 것들:

- **`pip install -r requirements.txt` 가 로컬에서 실패한다.**
  `psycopg2-binary==2.9.9` 가 Python 3.13 휠을 제공하지 않아 소스 빌드하다 막힘.
  CI는 3.12라 정상. 필요한 패키지만 개별 설치하면 된다.
- 개별 설치한 것: `ruff`, `black`, `langgraph`, `sqlalchemy`, `alembic`
- DB 테스트 16개는 `DATABASE_URL` 이 없어 자동 skip된다 (정상)
