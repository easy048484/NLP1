## 1. 판정 등급 체계 (판례 상태와 1:1 매핑)

| 등급 | 의미 | 판례 상태 | 카드 |
|---|---|---|---|
| 🟢 확인됨 | 요건 기재 확인 | — | 없음 |
| 🔴 확인 안 됨 | 무효 방향 판례 확립 | 확립 판례 존재 | 1장 |
| 🟡 쟁점 있음 | 사실관계 따라 갈림 | 판례 분기 | 2장 나란히 |
| ⚪ 참고 | 법정 요건 아님 | 해당 없음 | 없음 |
| ❓ 확인 대기 | 텍스트로 판별 불가 | — | 사용자 질문 |

**설계 원칙: 신호등 색은 우리의 판단이 아니라 판례의 확립/분기 상태를 그대로 반영한다.**

## 2. 요건별 판정 정책 (자필증서, 민법 §1066)

### 2-1. 연월일
- 년·월·일 3요소 모두 기재 → 🟢
- 일(日) 누락 ("2026년 5월") → 🔴 [연월일 미기재 무효 판례]
- 아예 없음 → 🔴 [동일 카드]
- 말로 특정 ("칠순 기념일에") → 🟡 [무효 판례 + 특정가능시 유효 사례, 2장]
- 날짜 복수 혼재 → 🟡
- ⚠️ 판정은 룰 엔진. LLM은 날짜 문자열 추출만.

### 2-2. 주소
- 번지/동·호수까지 기재 → 🟢
- 시·구 수준까지만 (동/구까지만, 지번 없음) → 🔴 [주소 누락 무효 판례와 동일 적용 — 다른 장소와 구별되는 정도의 표시를 갖추지 못한 것으로 봄]. 본문에 불완전하게라도 주소가 있는 상태이므로 아래 봉투 확인 질문은 트리거하지 않고 🔴로 바로 확정한다.
- 아예 없음(absent) → 🔴 [주소 누락 무효 판례], 이 경우에만 추가 확인 질문(텍스트로 판별 불가): "주소가 유언장 본문이 아니라 봉투에 적혀 있나요?"
  - 예 → 🟡 envelope_or_minor_discrepancy [97다38510 — 주소도 봉투에 기재해도 무방하다는 판례 참조, 개별 판단 필요]
  - 아니오 → 기존 🔴 판정 유지
  - ⚠️ 봉투 질문은 "본문에 주소가 아예 없어야" 성립한다. 시·구 수준까지만 적힌 경우(city_district_only)는 본문에 이미 주소가 있으므로 "봉투에 적혀 있나요?"라는 질문 자체가 말이 안 돼 대상에서 제외한다 (requirements.json의 address.followup.trigger_conditions: ["absent"]).
  - ⚠️ "지번이 실제와 근소하게 다른 경우"는 판례 근거 미확보 + 실제 주소 대조가 서비스 범위 밖이라 조건에서 제외함

### 2-3. 성명
- 기재 → 🟢 / 없음 → 🔴 [근거: §1066 조문. 판례 카드 없어도 무방]
- 호·아호 등 이례 표기 → 🟡 (동일성 인정 여부 쟁점)

### 2-4. 전문 자서 (텍스트 판별 불가 → 사용자 확인)
- 질문: "유언장 전체를 직접 손으로 쓰셨나요? (타이핑·워드 출력 아님)"
- 예 → 🟢 / 아니오·일부 타이핑 → 🔴 [타이핑 유언 무효 판례]

### 2-5. 날인 (텍스트 판별 불가 → 사용자 확인)
- 질문: "도장 또는 지장(손도장)이 찍혀 있나요?"
- 도장/지장 → 🟢 (무인도 날인 인정 판례 있음)
- 서명(사인)만 → 🔴 [서명만으로 날인 불충족 판례]
- 없음 → 🔴 [동일 카드]

### 2-6. 간인 (법정 요건 아님)
- 체크 항목에서 제외. 여러 장 감지 시 ⚪ 참고 문구만.

## 3. 화면 문구 (확정)

### 3-1. 전체 요약 (4케이스)
- A. 전부 🟢:
  "**형식 요건상 문제가 발견되지 않았습니다.** 자필증서 유언의 5가지 형식 요건(자서·연월일·주소·성명·날인)이 모두 확인됩니다. 다만 이 점검은 형식 요건에 한정되며, 유언의 최종 유효성은 내용·작성 경위 등에 따라 달라질 수 있습니다."
- B. 🔴 포함:
  "**확인되지 않는 요건이 있습니다.** 아래 항목은 법원이 무효로 판단해온 사례와 같은 쟁점에 해당할 수 있습니다. 법률 전문가 확인을 권합니다."
- C. 🟡만:
  "**전문가 확인이 필요한 부분이 있습니다.** 형식상 명확한 문제는 발견되지 않았으나, 법원 판단이 사안에 따라 갈린 쟁점이 포함되어 있습니다."
- D. 사용자 확인 대기 (PENDING 항목 개수 n으로 동적 치환 — n=1이면 "한 가지", n≥2면 숫자 그대로):
  "**{n}가지만 직접 확인해주세요.** 텍스트만으로는 판별할 수 없는 항목입니다."
  예) n=1 → "한 가지만 직접 확인해주세요." / n=2 → "2가지만 직접 확인해주세요."

### 3-2. 요건별 문구 패턴
- 🟢: "✅ {요건}: 기재 확인" (+ 추출값 표시)
- 🔴: "❌ {요건}: {red_label}이 확인되지 않습니다" + "{쟁점}을 무효로 판단한 판례가 있습니다 (법원 사건번호)"
  - {red_label}은 요건명과 중복되지 않도록 requirements.json의 red_label 필드를 쓴다 (연월일→"날짜", 주소→"유언자 주소", 성명→"성명", 전문 자서→"자필 작성 여부", 날인→"도장·지장")
  - 판례 카드는 "[카드]" 표기 대신 precedents.json의 실제 사건번호를 괄호로 붙인다: precedent 타입은 "({court} {case_number})" (예: "(대법원 2009다9768)"), commentary 타입은 "(대한법률구조공단 해설)"
  - "→ 법률 전문가 확인을 권합니다" 줄은 항목마다 반복하지 않는다 — 상단 요약(케이스 B)과 §3-3 상담 연결로 갈음
  - 예외: 날인 RED의 fingerprint_seal_valid는 무효 판례가 아니라 반대 취지(지장도 인정)의 참고 정보이므로 카드가 아니라 들여쓴 참고 문구로 별도 표시: "   ℹ️ 참고: 지장(손도장)을 날인으로 인정한 판례가 있습니다"
- 🟡: "⚠️ {요건}: {쟁점}이 쟁점이 될 수 있습니다" + 분기 판례 카드 2장(사건번호 표기 동일 적용) + "→ 개별 판단이 필요합니다. 법률 상담을 권합니다"
- ⚪: "ℹ️ 참고: 간인은 법정 요건이 아니지만, 여러 장일 경우 위조 다툼 예방에 도움이 됩니다"

### 3-3. 상담 연결 (공공기관만 — 알선 리스크 0)
"📞 무료로 확인받을 수 있는 곳: 대한법률구조공단 132 (무료 법률상담) · 각 지역 지부. 유언 검인·공증 관련은 가까운 공증사무소에서 안내받을 수 있습니다."

### 3-4. 하단 고정 고지 (모든 결과 화면)
"이 점검은 민법 제1066조의 형식 요건에 대한 참고용 확인이며, 법률 자문이 아닙니다. 유언의 유효성에 대한 최종 판단은 법원과 법률 전문가의 영역입니다."

## 4. 문구 가드레일 (프롬프트에 그대로 이식)

1. 단정 동사 금지: "무효입니다/유효합니다" → "무효로 판단한 판례가 있습니다 / 문제가 발견되지 않았습니다"
2. 판단 주어는 항상 법원/판례 — 서비스가 판단 주체로 서지 않음
3. 🟢도 "문제가 *발견되지* 않았습니다" (발견 못 함 ≠ 없음)
4. 🟡는 행동(어디서 확인)으로 끝남. 🔴는 항목별로 반복하지 않고, 상단 요약(케이스 B)과 하단 132 상담 연결로 행동을 안내함
5. "청구하세요/하세요"류 지시 금지 — "권합니다"까지만

### 97다38510 — 한 판결이 세 법리를 커버함
이 판결 하나에 (a) 전자복사기 복사본은 자필증서 아님, (b) 주소는 전문을 담은
봉투에 기재해도 무방, (c) 날인은 인장 대신 무인도 유효 — 세 법리가 함께 들어
있다. 그래서 JSON에서는 쟁점별로 `typed_will_invalid`(a) 와
`fingerprint_seal_valid`(b·c) 두 id가 같은 사건번호를 인용한다. 사건번호가
중복돼 보여도 오류가 아니다.

### 향후 재사용 메모 — 유류분 소멸시효 (97다38510)
