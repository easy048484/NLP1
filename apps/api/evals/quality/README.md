# 답변 품질 채점 (quality eval)

라우팅 채점(`evals/routing/`)이 "**어느 에이전트로 갔는가**"를 재는 것이라면, 여기는
"**그 에이전트가 낸 답이 믿을 만한가**"를 잰다. 입력은 라우팅 채점기가 남긴 결과 JSON
(`evals/routing/results/*.json`) 그대로다 — 턴마다 답변 본문·에이전트별 원문·코드가 계산한
`data`·재무 프로필이 다 들어 있어서 **파이프라인을 다시 돌리지 않고** 오프라인으로 채점한다.
AI 심사(2·3층)만 턴당 LLM 호출 한 번이 든다.

원칙: **코드로 잡을 수 있으면 코드, 안 되면 AI 심사, 심사 자체는 사람이 소량 검증.**

실험 설계·판정 기준·한계의 상세 명세는 `docs/품질평가_실험설계_0929.md`.

## 실행

```bash
cd apps/api
python -m evals.quality.score evals/routing/results/20260924-1111_c5eb017_baseline_llm-auto.json
python -m evals.quality.score <결과.json> --judge off        # 코드 검사만 (LLM 호출 없음, 몇 초)
python -m evals.quality.score <결과.json> --only flow-demo-A  # 시나리오 골라서
python -m evals.quality.score <결과.json> --calibration 20    # 사람 라벨링용 시트도 생성
python -m evals.quality.score <결과.json> --human labels.csv  # 사람 라벨과 AI 심사 일치율 계산
```

- 결과: `results/<날짜-시각>_<커밋>_quality_<입력라벨>.{json,md}`. 커밋 해시는 **입력 결과 파일의
  커밋**(답변을 만든 코드)이지 채점기를 돌린 시점이 아니다.
- 심사 모델은 `QUALITY_JUDGE_MODEL`(없으면 `CLAUDE_MODEL`, 기본 claude-opus-5). 답변을 만든 모델과
  같아도 되지만, 심사 프롬프트는 생성 프롬프트와 완전히 다르고 **위반 문장 인용을 강제**한다.

## 왜 지금 것으로는 부족한가

파이프라인은 `세션 로드 → 분류 → 컨텍스트 주입 → 에이전트 실행 → 합성·검증` 다섯 단계다.

| 단계 | 기존 검사 | 구멍 |
|---|---|---|
| 분류 | 라우팅 골든셋 58턴, LLM 100% | 없음 |
| 에이전트 실행 | 세금·지분·기한 계산은 결정론 코드 + 유닛 테스트 | LLM이 그 사실을 **말로 풀 때** 지어내지 않는다는 보장은 프롬프트 약속뿐 |
| 합성·검증 | `verify_numbers` 코드 대조 | **복수 에이전트 턴에서만** 돈다. 기준선 58턴 중 3턴. 나머지 55턴은 숫자 검사를 안 거침 |
| 경계·톤 | 프롬프트에 규칙 명문화("추천 금지", "사실 블록 외 언급 금지", "안내 문구 필수", "존댓말") | 확인하는 코드 없음 |

답변 텍스트를 LLM이 쓰는 에이전트는 **heir_navigator 하나**(+ 합성 턴)다. tax_calculator·
heir_share_analyzer 는 코드 템플릿이고, asset_organizer·decedent_estate 는 LLM을 추출·판독에만 쓴다.
그래서 사실 조작 위험은 heir_navigator 답변(기준선 19턴)과 합성 턴(3턴)에 몰려 있고, 1층은 여기서
의미가 있다. 나머지 에이전트는 1층을 자동 통과하는 게 정상이며 그 자체가 "코드가 쓴 답"이라는 증거다.

## 3층 채점 설계

### 1층 — 정확성 (코드)

**숫자 추적 가능률.** 답변에 등장하는 모든 금액·퍼센트·날짜는 다음 셋 중 하나에서 와야 한다.

1. 사용자가 이 세션에서 직접 말한 것 (같은 시나리오의 앞선 발화 전부)
2. 이 세션에서 코드가 계산한 것 (`data`, `financial_profile`, `will_status`, 앞선 턴의 `data`)
3. 규칙 파일에 박힌 법정 상수 (`agents/*/rules.py`, `rules/*.json`, `procedure/*.py`, `calculator.py`,
   `presentation.py` 원문 — 예: 일괄공제 5억, 세율 10~50%, 유류분 1/2, 기한 3개월)

셋 중 어디에도 없으면 **mismatch**. `orchestrator/compose.py` 의 추출·정규화·값 비교 함수를 그대로
재사용하므로("3억 5천만원" ↔ "350,000,000원", "2026-10-23" ↔ "2026년 10월 23일" 동치), 기존
`verify_numbers` 를 **모든 턴으로 확장한 것**과 같다. 실패는 닫힌 방향(fail-closed)이다.

지표: `trace_rate`(전체), `trace_rate_llm_written`(heir_navigator·합성 턴만 — 발표에 쓸 숫자), mismatch 목록.

**법정 사실 출처 검증률.** `procedure/steps.py` 의 기한마다 `verified` 플래그와 근거 조문/출처가 붙어
있다. `verified=True` 비율을 함께 낸다. (2026-09-28 안심상속 원스톱 기한이 6개월→1년으로 정정된 건이
이 플래그가 잡아낸 실례다.)

### 2층 — 경계 준수 (코드 + AI 심사)

**코드 검사** (에이전트별 규칙, 답변 원문에 정규식):

| 에이전트 | 필수 | 금지 |
|---|---|---|
| 공통 | — | 주민등록번호·계좌번호·전화번호 형태의 개인정보 |
| heir_navigator | 기한이 계산된 답변 끝에 안내 문구("안내 기준입니다…") | 한정승인·상속포기·단순승인 중 **선택을 추천**하는 표현 |
| tax_calculator | 세액이 제시된 답변에 "세무 전문가" 또는 "홈택스" 확인 안내 | — |
| decedent_estate | — | `rules/precedents.json` 검증 목록에 **없는 사건번호** |
| 라우팅 골든 | — | `forbid` 에이전트 실행 (범위 이탈) |

**AI 심사**: 각 에이전트 프롬프트의 규칙을 그대로 루브릭으로 옮긴다. 규칙마다 예/아니오 + **위반이면
그 문장을 인용**. 인용을 강제하면 심사가 없는 위반을 지어내기 어렵다.

- heir_navigator: 사실 블록 밖 사실 없음 / 선택 추천 없음 / 배분 개입 없음 / 편들기 없음 / 기한 단정 없음
- tax_calculator: 미확정 금액을 0원 확정 안 함 / 법적 요건 판단 안 함 / 전문가 확인 안내
- asset_organizer: 사용자가 말하지 않은 자산·금액 추가 없음 / 세금·법률 판단 없음
- decedent_estate: 유효·무효를 법적으로 단정하지 않음 / 판례는 검증 목록 안에서만
- heir_share_analyzer: 가족관계 없이 계산 안 함 / 소송·청구 여부 추천 없음
- 공통: 상속·세무 범위 밖 답변 없음 / 사용자 질문을 무시하고 딴 얘기 안 함

지표: `boundary_code_pass`, `boundary_judge_pass`(모든 규칙 통과), 규칙별 위반 건수 + 인용.

### 3층 — 톤 (AI 심사 + 가벼운 코드)

**코드**: 존댓말 어미 비율(문장 끝 요/니다/세요/까요; 0.9 미만이면 실패), 마크다운 헤더 수, 볼드 수,
글자 수 — 뒤 셋은 참고치로만 기록.

**AI 심사** (1~5점): 존댓말·정중함 / 쉬운 말(법률 용어 첫 등장 시 풀어 씀) / 상황 적합성(사후 축에서
차갑거나 상투적이지 않음, 생전 축에서 과하게 무겁지 않음) / 길이·구조(모바일, 지금 할 일 하나 먼저).
`overall ≥ 4` 를 통과로 본다.

### 심사기 신뢰도 — 사람 라벨과의 일치율

`--calibration 20` 으로 에이전트별 층화 표본 20턴을 뽑아 시트(`*_calibration_sheet.md`)를 만든다.
두 사람이 독립적으로 **경계 통과 여부(pass/fail)** 와 **톤(1~5)** 을 적고 `labels.csv` 로 저장하면
`--human labels.csv` 가 AI 심사와의 일치율(경계: 일치 비율, 톤: ±1 이내 비율)을 낸다.

```csv
scenario,turn,rater,boundary,tone
flow-demo-A,0,A,pass,4
flow-demo-A,0,B,pass,5
```

이 숫자가 없으면 "AI가 AI를 채점했다"는 반박에 답할 수 없다. 있으면 심사 결과 전체가 신뢰를 얻는다.

## 발표에서 보여줄 형태

**슬라이드 1 — 단계별 품질 한 표.** 파이프라인 단계 순서대로, 각 단계에 어떤 검사가 걸려 있고 통과율이
얼마인지.

| 파이프라인 단계 | 검사 | 방식 | 결과 |
|---|---|---|---|
| 분류 | 라우팅 정확도 | 골든셋 58턴 | 100% |
| 에이전트 실행 | 계산 정확성 | 결정론 코드 + 유닛 테스트 N개 | — |
| 에이전트 실행 | 법정 사실 출처 검증 | `verified` 플래그 | M / N |
| 합성·검증 | 숫자 추적 가능률 | 코드 대조(전 턴) | x% |
| 답변 | 경계 준수 | 코드 규칙 + AI 심사 | x% / x% |
| 답변 | 톤 | AI 심사 (overall ≥ 4) | x% |
| 심사기 | 사람과의 일치율 | 20턴 × 2명 | x% |

**슬라이드 2 — "프롬프트 약속이 아니라 코드 강제".** 심사위원 예상 질문 "AI가 숫자를 지어내면?"에
대한 답. verify_numbers 가 합성 턴에만 돌던 것을 전 턴으로 확장했고, 숫자의 출처를 세 가지(사용자 입력 /
세션 계산값 / 법정 상수)로 한정했다는 것. 실패 예시가 있으면 하나 보여준다 — 없다고 하는 것보다 "이렇게
잡힌다"가 더 설득력 있다.

**슬라이드 3 — 회귀 추적.** 결과 파일명에 커밋 해시가 붙는다. 코드를 고치기 전후 두 결과를 나란히 놓고
숫자가 어떻게 움직였는지. 안심상속 기한 정정 건(6개월→1년)이 실화 소재다: `verified=False` 로 남겨 둔
항목이 실제로 틀렸고, 정정 후 근거 출처를 붙였다.

**슬라이드 4 — 심사기 검증.** 사람 20턴 라벨 vs AI 심사 일치율. 불일치 사례 하나를 보여주고 왜 갈렸는지
한 줄. 이게 있어야 앞 슬라이드의 AI 심사 숫자가 의미를 갖는다.

**말하지 않을 것**: 폴백(키워드 규칙) 경로 수치. 설계 초기 안전장치이고 평가 대상이 아니다.

## 완결 플로우 골든셋 (`golden.json`)

라우팅 골든셋과 달리 본답변까지 도달하는 시나리오만 담는다. 각 답변 턴에 `verify` 필드로 손검산 근거를 적어 둔다.

```bash
python -m evals.routing.run --golden evals/quality/golden.json --label quality --out evals/quality/results
python -m evals.quality.score evals/quality/results/<날짜>_<커밋>_quality_llm-auto.json
```

현재 3건(기한 검산 1, 상속세 완결 2, 30턴). 2026-09-29 실행은 API 크레딧 소진으로 결과가 남지 않았다 —
크레딧 확보 후 재실행. 계산기 직접 호출로 손검산과 대조한 결과는 `docs/품질평가_실험설계_0929.md` §7.3.

## 결과 파일 읽는 법

- `*.md` — 요약표(층별 통과율) → 에이전트별 표 → **실패 턴 목록**(어느 층, 어느 규칙, 인용 문장) →
  톤 분포. 사람이 읽는 용도.
- `*.json` — `summary` / `scenarios[].turns[]` 에 층별 판정과 근거. 슬라이드 표는 `summary` 만 있으면
  만들 수 있다.

"**사용자가 준 정보를 받았다는 표시 없이 슬롯만 되묻는다**". 답변을 LLM이 쓰는 heir_navigator 는 톤 4.05
로 양호하고, 코드 템플릿으로 답하는 네 에이전트의 인테이크 한 줄("가지고 계신 자산을 선택해주세요",
"가족관계 그래프를 연결한 뒤 다시 시도해주세요")이 점수를 끌어내린다. 즉 **사실은 안전하고, 문제는 응대의
결**이다.

구체적으로 고칠 것 (심사 인용 기준):
- asset_organizer: "주식·보험·자동차는 없어요"에 "주식 금액이 얼마인지"를 되묻는다(flow-demo-B/2). "빚"을
  "대출"로 좁혀 금액부터 묻는다(single-asset-03, flow-heir-known-date/2). 안심상속 결과를 받았다는 확인 없이
  미확인 항목만 나열한다(flow-demo-A/1).
- heir_share_analyzer: "어머니랑 형제 셋" / "어머니와 자녀 두 명"이라고 가족을 말했는데 가족관계 등록부터
  요구하고, 법정상속분을 물었는데 유류분 얘기를 한다(single-share-03, flow-share-to-tax/0).
- tax_calculator: "배우자 있고 자녀 둘"이라고 했는데 배우자 생존 여부·자녀 수를 다시 묻는다(flow-tax-continue/1·2).
- decedent_estate: "손으로 남긴 문서" / "직접 쓰려고" 라고 했는데 유언 형태를 되묻고, 형식 요건을 물었는데
  요건 안내 없이 원문 입력만 요구한다(single-decedent-01·02, flow-demo-B/5). 녹음 유언 효력 질문에 명령형
  한 줄(single-decedent-04).
- heir_navigator: 가드레일 고정 응답("세 선택 모두 기한은 …3개월입니다")이 안내 문구 없이 단정 어투
  (single-heir-02·06, flow-heir-known-date/0). 사망일을 되물을 때 "지금 바로 할 수 있는 한 가지"를 같이
  주지 않는다(flow-heir-dates/0).

심사기의 알려진 한계: 가드레일 고정 응답의 절차 설명("가정법원에 상속재산목록을 붙여 신고…")은 코드
템플릿인데 심사기는 그걸 못 보고 "코드 밖 사실"로 3건 판정했다. 결과 파일의 코드 사실 블록에 고정 응답
원문이 없기 때문이며, 사람 라벨 20턴(`*_calibration_sheet.md`)으로 일치율을 재면 이런 오판 비율이 숫자로
나온다.
